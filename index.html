The same seed gives the same key

The aim: for African certification authorities to issue ordinary X.509 certificates, which serve every purpose and are read by all software, but whose keys come from a generator mastered from end to end.

The two primes of an RSA key are built from a seed, by a public computation described in full. The same seed gives the same key, on any machine, with any program written from the text.

Whoever holds a key can therefore prove that it comes from that computation and from nothing else: they make it again elsewhere and compare. A faulty or malicious generator does not pass that test.

The computation is not new: it is the Shawe-Taylor provable prime construction published in FIPS 186-4. The standard makes it mandatory, describes it without cross-reference, attaches a generation record to it and defines the conformity checks.

What the tests check

  • The generator finds the three official NIST cases (ACVP, RSA KeyGen FIPS 186-4, method B.3.2).
  • The two implementations give the same keys in 2048, 3072 and 4096 bits.
  • OpenSSL recognises the keys, signs and verifies with them.
  • A chain root → issuing authority → certificate passes the twelve checks and OpenSSL's strict verification, and ten faulty chains are each stopped by the expected check.

Try it

Generate a 3072-bit key
python3 rsagraine.py generer --bits 3072 --sortie cles/
Check that the seed gives back the key of the record
python3 rsagraine.py verifier --graine cles/graine.hex --fiche cles/fiche.json
Have the second implementation replay the vectors
node independant/gcr.js

Three files are written: the private key, the seed and the public record. The seed is worth the private key.

What this does not do

  • The seed is worth the private key. Replay is done by the holder or their auditor, not in public.
  • The reference implementation is not constant-time. It serves to produce and check keys on a machine you control, not on one an adversary observes.
  • The quality of the seed is that of the system's randomness. A weak seed gives a weak key.
  • The authority tool does not yet produce the revocation lists or the register that GCR-0002 requires, and issues server certificates only.
  • RSA is not eternal. A large enough quantum computer breaks it; official timetables plan its withdrawal in the 2030s.
  • Read by all does not mean trusted by all. A root must be listed in trust stores to be trusted without any setting.
